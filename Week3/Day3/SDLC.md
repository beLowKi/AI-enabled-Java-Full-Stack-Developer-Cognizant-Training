
Stands for software development lifecycle. It's a multi-stage framework for developing software. 

## Phases/Stages

### Requirement Collection

Software and business requirements are determined. In Agile, this usually means meeting with the Product Owner and hearing what they want from the app. More generally, this role is called the "Business Analyst".

### Analysis

The problem scenario is broken down into functional and non-function requirements.

#### Functional

These are explicit software requirements/features.

- Calculate salary
- Generate a payslip
- Record attendance

#### Non-Functional

These don't map to exact features. They are usually accomplish through a series of functional requirements

- Performance optimization
- Security
- High level UX goals

### Design

Determining architecture: programming language, tools, database setup, etc. This step is more technical than prior planning stages.

### Development

Writing the code and anything else that needs to be made.

### Testing

Testing that program fulfills the requirements

### Deployment

Release to production

### Maintenance

Continuously monitor and update the program when needed

## SDLC Approaches

### Waterfall 

Sequential SDLC approach. Each stage is reach once and must be fully complete before the program reaches the next stage. This leaves no room for changes to requirements and/or design, or at least it works best when things are set in stone. 

### Agile

Cyclical SDLC approach where the program is split into "Sprints"--finishing small portions of the program at a time. Each Sprint goes through all 7 stages at a faster pace. These iterations continue until all requirements have been met. The Product Owner is met with more frequently, so collecting new or updating existing requirements, change is much easier to handle.

Collaboration, adaptability, and continuous improvement are (alleged) features of Agile, and one proponent of this is [[Scrum]]
